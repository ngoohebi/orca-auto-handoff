For Orca · Claude, Codex, Antigravity, OpenCode, Devin

Hit a rate limit? Auto-switch to your next account.

Automatic account switching for Orca. Claude to Claude, Codex to Codex: a session always keeps its provider. Auto Hand-off runs the accounts Orca manages as one pool per service. When a session hits a limit, the plugin cools that account down and hands the session off to the next account with room. A Claude session is resumed there as the same session, with its context and the first message already typed. Codex, Antigravity, OpenCode and Devin cannot resume a session on another account: they start a new session there from a summary of the old one.

How it works

Six steps, one hand-off, no cascade

Detection runs when a pane turns done or waiting. A limit banner among the last five meaningful lines, shaped like a CLI status line and not an agent reply, starts the sequence.

Cool down

The limited account is set aside until the reset time parsed from the banner, else Orca's resetsAt, else the default cooldown.

Pick the next

Auto takes the account of the same service that will last longest at its pace; Custom order takes the highest account in your order that has room.

Select

Runs orca account select, so new sessions use the new account too.

Close

Reads the input box twice, a second apart, and once more right before closing the pane, through the host API or the Orca CLI when the pane is in another workspace. Typing in progress calls the hand-off off. If the hand-off fails before the pane is closed, the next account is tried, up to three times.

Resume

Calls agent.resume on the same session id. Services that cannot resume (Codex, Antigravity, OpenCode, Devin) start a new session from a summary instead (at most 4,096 characters), and only at a real limit.

First message

Types the configured message, "Continue." by default, and the agent carries on. Only where a limit or API error interrupted the work: a session that had finished its turn and was handed off early is resumed and left ready. Plain text you had typed and not sent is put back, unsent (Claude).

Triggers

Every reason a session hands off, and what happens

Each banner is handled once per session, so a transcript Orca redraws after a restore is never handed off twice. Usage numbers come from Orca's own orca account list. The plugin never reads tokens or keychains.

TriggerAction
Rate-limit banner in the session's latest outputCool the account down until the parsed reset time, hand off, resume.
Model-specific cap (for example a Claude Fable weekly cap)Hand off to an account known to have room for that model, then type /model <next> from Model fallback in place, then try an account not known to be full for that model, then wait. /model is never typed into a pane whose input box holds unsent text.
API error (529, overloaded, stream disconnected)Type the first message again after a Fibonacci backoff from 5 s to 120 s, up to API error retries (0 = never). Only while the pane is still between turns, and never into an input box that holds unsent text.

The account left behind stays out of rotation until its window resets. While you are at Orca, and with At limit, this never happens: a session hands off only at a real limit.
A limit hits the session on screenAsk me first (default): you are notified and the panel asks "Hand off the session on screen?" with Hand off now or Not now; no answer acts like the next choice, Not now waits for another tab. Wait, then count down: wait while you are using Orca; otherwise a 60-second countdown with a notification. Wait for me: hand off once you switch tabs. Move right away: no waiting. A waiting session also offers Hand off now (which says why when it cannot), Not now and Don't hand off.
Every account of the service limitedWait and resume: the session waits and continues when the earliest account frees up; if its own account frees up first, it continues where it is. Carry on in the waiting pane yourself and the wait ends. Close it yourself and the session is not resumed. Stop: the session stops and you are told, also one waiting on screen.
A higher account in your order is healthy again (Custom order)Switch back. New sessions use it, and with Early when away, once you are away, Claude sessions on lower accounts hand off back when they finish a turn or sit idle; they are resumed and left ready, without the first message.
A Claude session idles on an account that is about to run out, or another account's weekly quota would expire unused (Early when away, you away)Hand it off after Hand off idle sessions after, 15 minutes by default.

Guards on hand-offs

Plain text you typed and did not send goes with a Claude session and is put back unsent; if it cannot be put back, the notification quotes its first 300 characters and History keeps all of it to copy. Pasted images or blocks, text over 4,000 characters, text with escape sequences, queued messages, and unsent text in Codex, Antigravity, OpenCode or Devin keep the session where it is until you send or clear it. The session on screen is never handed off early. Early, idle and switch-back hand-offs also need at least 10 % more room on the target, and change a service's selection at most once per 5 minutes; hard limits ignore those two. Claude's grey prompt suggestion is reported like typed text, so it may come back as real text, never sent without Enter.

Panes it did not start

A restored pane has no recorded account. If it hits a limit while Orca shows plenty of room on the active account, the plugin cools nothing and simply resumes the session there.

Off switches

Detection is heuristic. One switch pauses every service, each service has its own Automatic hand-off switch, and the Skip switch on an account card keeps that account out of automatic rotation. There is no manual or custom mode: these switches are it. While Orca cannot give the plugin your settings, or the upgrade from 0.2 is not finished, nothing is handed off automatically and the panel says so.

How it decides

Four choices, sensible defaults

Out of the box the plugin runs Auto · Early when away and picks the next account by how long it will last. While you are using Orca (and right after it starts) a session hands off only at a real limit, so it is seldom moved under you; once you have been away for 10 minutes, Claude sessions hand off shortly before an account runs out, so work does not stop at a limit. You count as here while you send or answer a prompt in the session on screen, type in a waiting session, switch tabs, use the panel or run one of its commands. Four basic settings in the panel's Settings tab change what runs: Pick the next account, When to hand off, When everything is used up and Session on screen. The rest is folded away under Advanced.

Auto

The default. The account with the most room, judged by how fast each one is being used. Spends weekly quota that would expire unused first.

Custom order

Your ranking, set with the arrows on the account cards. Hands off to the highest account with room, and goes back to a higher one once it is free again.

Early when away

The default. Once you have been away a while, Claude sessions hand off shortly before an account runs out. While you are using Orca, sessions hand off only at a limit. Other services always hand off only at a limit.

At limit

A session hands off only when it hits a limit. Each account is used to the end.

Session on screen

Every pane of the tab Orca is showing. Never handed off early. At a limit, Ask me first (default) asks in the panel; unanswered, it waits while you are using Orca, then counts down. Or: Wait, then count down, Wait for me, Move right away.

The badge next to the panel's title says what is happening now: ● Auto · Early when away · on (green, you are away), ◐ … · waiting (you are here), ○ Auto · At limit (grey) or ■ Paused (amber). When everything is used up, the session waits for the first account to reset and continues by itself, or, with Stop, stops and you are told. There is no manual or custom mode any more: pause, or turn off a service's Automatic hand-off.

Coming from 0.2? At the first start of 0.3.0 your old settings are read once and turned into the new ones: my-order or an account order becomes Custom order; at-limit, a running-sessions limit or "Switch at usage threshold" off becomes At limit; earlier becomes Early when away, 25 minutes before running out; "Wait for reset" off becomes Stop; "Retry on API errors" off becomes 0 retries; the idle time in seconds becomes minutes, rounded up. A setup that never handed off by itself gets automatic hand-off paused once, with a notification. Until that upgrade has finished, nothing is handed off automatically and the panel says "Auto Hand-off is finishing the upgrade".

Providers

Same service only, by design

A Claude session hands off to another Claude account and a Codex session to another Codex account, never across services. How the session continues depends on what the service can do.

Claude resume by session id

Every Orca Claude profile shares the ~/.claude/projects transcripts, so the exact session resumes on the next account. Usage for an account that has not run yet is unknown; such an account is a last resort, after every account with known room.

Codex, Antigravity, OpenCode, Devin summary

These keep sessions per account, so the same agent is started on the next account with a hand-off summary of at most 4,096 characters: why the previous run stopped, the session title, branch, git status, git diff --stat and the last 40 lines of output. OpenCode and Devin report no usage, so only rate limits hand them off.

In the app

Panel, commands, console line

Panel

Gauge icon in the right sidebar. The badge next to the title says what is happening now (● on, ◐ waiting, ○ at limit, ■ paused, in one fixed-width slot). One section per service, with its brand colour, its own Automatic hand-off switch on a line of its own and "n of m ready"; the service on screen comes first, marked "· on screen". Each account with 5-hour, weekly and model bars, a status word, a cooldown with its reason and Clear, a Skip switch, arrows for Custom order and, on each standby account of the service on screen, Hand off to this account (it asks first; new sessions then start on that account and the session on screen hands off too if it is between turns; text that cannot go along is shown, and the panel asks once more). The Claude section has the Status line switch and, while it is on, the Status line header. Plus the pause switch, a Waiting box ("Hand off the session on screen?" with Not now / Hand off now; Don't hand off; Cancel), History in words with local times (Limit reached, Running low, Back to preferred …), and a Settings tab with Basic and Advanced settings, where each dropdown lists its default first, e.g. "Auto (Default)". There is no status bar item.

Commands

Start new Claude or Codex sessions on the next account. Hand off this workspace's session to another account. Pause or resume automatic hand-off. Refresh usage. Install or remove the console status line. Running one counts as a sign that you are here.

Console status line for Claude panes

Orca's own hook leaves Claude Code without a visible status line. The plugin's wrapper forwards every payload to Orca, then prints one row per account of the pane's service: percent left in the 5-hour, 7-day and best-model windows, green above 50 %, red at 20 or less. Every row shows the same numbers as the panel, and idle panes refresh every 10 seconds. ▶ marks this pane's account, ⏸ a cooldown. About 40 ms per render, no CLI calls.

Permissions

What it runs, and what it never touches

Orca shows you exactly this before the plugin is enabled, and the approval fingerprint is bound to the plugin, version, files and access.

Host capabilities

  • agent:read, agent:launch to see pane status and resume sessions
  • terminal:read, terminal:send to read the last lines and type the first message
  • workspace:read, notifications:show
  • storage:own, settings:own for history and your settings

Outside the host API

  • Runs the orca CLI: account select, account list, terminal close, terminal send, terminal read (only to ask whether a pane holds unsent text; that text is put back after a hand-off, or shown when the panel asks before a hand-off by hand), terminal list (only to see which terminal tab is in front). Always an argument list, never a shell.
  • For a project on a paired Orca server: loads Orca's own runtime client from the app bundle (cli/runtime/client.js, and before it the store helper shared/remote-runtime/host-store/runtime-environment-store-execution.js) to list and select that server's accounts, and to look up, read-only, which Orca a workspace runs on. The list call passes refreshUsage: false, refreshStaleUsage: true: no forced refresh, but that Orca may refresh readings it considers stale. These are Orca internals, not a published API
  • Writes its status file (readable by you only, mode 0600, since it names your accounts) and the status line script under ~/.orca/account-rotator/, and, only when you install the console status line, that workspace's .claude/settings.local.json
  • Runs git status and git diff --stat for hand-off summaries
  • Never reads tokens, keychains or credential files
  • A hand-off summary carries up to 40 lines of the previous agent's output, so treat it like any pasted terminal output
Known limitations

Read these before you rely on it

None of them interrupts a turn or crosses services. The README lists the rest.

When a session hands off

  • Closing a pane also stops the background processes the agent left running in it (a dev server, a watcher)
  • If the resume fails after the pane was closed, the session stays closed. You are notified and can reopen it; the conversation is not lost
  • Codex, Antigravity, OpenCode and Devin start a new session from a summary, so they hand off only at a real limit or when you ask
  • If Orca cannot be asked whether a session is mid-turn or holds unsent text, it is not handed off until Orca answers. The same holds while Orca cannot say where a workspace runs; it is asked again at the next check
  • Orca cannot say whether you are in front of it, only which tab is shown: a session on screen you are reading without typing can hand off after the countdown if you do not answer the panel's question
  • Claude's grey prompt suggestion is reported like typed text, so it can come back as real text after a hand-off (never sent without Enter). The scroll position is not kept

Commands and the status line

  • The hand-off command picks the first idle agent when a plain shell tab is in front
  • The next-account commands change the account for new sessions at once, and Orca may show its restart prompt. You do not need to press Restart
  • Hand off to this account turns automatic hand-off off for that service, until you turn it on again
  • The console status line needs sh (no Windows), and installing it writes .claude/settings.local.json in the repository
Install

Two commands and an approval

  1. Install from GitHub. Orca pins the newest version tag and prints what the plugin would be granted, along with a fingerprint.

    orca plugin install ngoohebi/orca-auto-handoff

  2. Approve with that fingerprint. The command is printed for you; it looks like this.

    orca plugin install ngoohebi/orca-auto-handoff --approve ap1-…

  3. Add a second account for the service in Orca, if you have not already. Done: open the Auto Hand-off panel (gauge icon, right sidebar). Optionally choose Custom order in its Settings tab and arrange your accounts with the arrows.
