Hit a rate limit? Auto-switch to your next account.

Automatic account switching for Orca. Claude to Claude, Codex to Codex: a session always keeps its provider, so the model and the context never change. Auto Hand-off runs the accounts Orca manages as one pool per service. When an agent pane prints a limit, the plugin cools that account down, selects the next healthy one, and resumes the same session there, with the first message already typed.

How it works

Six steps, one swap, no cascade

Detection runs when a pane turns done or waiting. A limit banner among the last five meaningful lines, shaped like a CLI status line and not an agent reply, starts the sequence.

Cool down

The limited account is parked until the reset time parsed from the banner, else Orca's resetsAt, else the default cooldown.

Pick the next

The strategy chooses another healthy account of the same service from your chain.

Select

Runs orca account select, so new launches use the new account too.

Close

Closes the limited pane, through the host API or the Orca CLI when the pane is in another workspace.

Resume

Calls agent.resume on the same session id. Services that cannot resume get a handoff prompt instead.

First message

Types the configured message, "Go continue." by default, and the agent carries on.

Triggers

Every reason a pane moves, and what happens

Each banner is handled once per session, so a transcript Orca redraws after a restore is never switched twice. Usage numbers come from Orca's own orca account list. The plugin never reads tokens or keychains.

TriggerAction
Rate-limit banner in the pane's latest outputCool the account down until the parsed reset time, switch, resume.
Model-specific cap (for example a Claude Fable weekly cap)Smart and Follow my order: move to an account known to have room for that model, then type /model <next> from Model fallback in place, then try an account not known to be full for that model, then wait. Custom: /model <next> first, and switch accounts only when the list runs out. /model is never typed into a pane whose input box holds unsent text.
API error (529, overloaded, stream disconnected)Type the first message again after a Fibonacci backoff from 5 s to 120 s, up to the retry limit. Only while the pane is still between turns, and never into an input box that holds unsent text.
Auth failure12-hour cooldown on that account, then switch.
A turn ends while the account is over a thresholdSwitch. The account left behind stays out of rotation until its window resets. Smart, the default, also leaves an account shortly before it runs out (about 10 minutes ahead at the current pace), between turns or when the session is idle. In custom mode thresholds default to 100 %, so this is reactive only.
Every account of the service limitedPark the session and wake it when the earliest account frees up. Carry on in the parked pane yourself and the wait ends. Close it yourself and the session is not resumed.
A higher-priority account is healthy againSwitch back. New launches use it, and sessions on lower accounts move back when they finish a turn or sit idle.
A session idles on an over-threshold accountMove it after Move idle sessions after seconds, 900 by default.
orca account select fails for an accountSkip that account for 10 minutes and take the next.

Guards on moves

No automatic move closes a pane holding unsent text. At a hard limit, or when a parked session is due, you are told once and the move is carried out as soon as the text is sent or cleared. Threshold, idle and switch-back moves also need at least a 10 % headroom gap, and change a service's selection at most once per 5 minutes; hard limits ignore those two. Claude's grey prompt suggestion is reported like typed text, so it can still hold back an automatic early move; the panel's manual switch asks instead.

Panes it did not start

A restored pane has no recorded account. If it hits a limit while Orca shows plenty of room on the active account, the plugin cools nothing and simply resumes the session there.

Off switches

Detection is heuristic. One toggle pauses every service, each service has its own switch, and exclude keeps named accounts out of automatic rotation.

Strategies

Choose how the pool is spent

Out of the box the plugin runs in Smart mode (Auto-switch): it looks ahead, leaves an account shortly before it runs out, and picks the next one by how long it will last. Follow my order follows your account order instead. The strategies below are the Advanced settings, used when Auto-switch is custom (kept automatically for settings changed in an earlier version). The chain setting orders accounts within each service, by email or seat key. Example: me@example.com, claude:*. Empty means Orca's order.

drain

Stay on an account until it is limited, then take the next in chain order.

balanced

Always the account with the most room.

priority

Always the first healthy account in the chain.

soonest-reset

The account whose weekly window resets first, so expiring usage is spent before it is lost.

manual

Never switch automatically. The panel and commands still work.

Switch back applies in Follow my order, and in custom mode (on by default) for drain and priority, where the chain is a priority order. Once an earlier account is out of cooldown and under its thresholds, new launches use it again and lingering sessions migrate back after their next turn, or after sitting idle.

Providers

Same service only, by design

A Claude pane moves to another Claude account and a Codex pane to another Codex account, never across services. How the session continues depends on what the service can do.

Claude resume by session id

Every Orca Claude profile shares the ~/.claude/projects transcripts, so the exact session resumes on the next account. Usage for an account that has not run yet is unknown; such an account is a last resort, after every account with known room.

Codex, Antigravity, OpenCode, Devin handoff

These keep sessions per account, so the same agent is started on the next account with a handoff prompt: why the previous run stopped, the session title, branch, git status, git diff --stat and the last 40 lines of output. OpenCode and Devin report no usage, so only rate limits move them.

In the app

Status bar, panel, commands, console line

Status bar

One glance at every service: accounts in rotation and the 5-hour and weekly usage of the active one. Warning tone at 80 %, danger while a session is parked. Click it to move Claude to the next account.

Claude 2/3 · 7%·18% | Codex 1/3 · 84%

Panel

Gauge icon in the right sidebar. Each account with 5-hour, weekly and model bars, active and limited badges, a cooldown countdown, Clear and, on each standby account, Hand off to this account (it asks first, then new sessions start on that account and the session in the current tab moves too if it is between turns; when it shows unsent text, which includes Claude's grey prompt suggestion, the panel shows the text and asks once more before moving it). Plus the automatic-switching toggle, parked sessions and the swap history.

Commands

Switch Claude or Codex to the next account. Move this workspace's agent to another account. Pause or resume automatic hand-off. Refresh usage. Install or remove the console status line.

Console status line for Claude panes

Orca's own hook leaves Claude Code without a visible status line. The plugin's wrapper forwards every payload to Orca, then prints one row per account of the pane's service: percent left in the 5-hour, 7-day and best-model windows, green above 50 %, red at 20 or less. ▶ marks this pane's account, ⏸ a cooldown. Permissions

What it runs, and what it never touches

Orca shows you exactly this before the plugin is enabled, and the approval fingerprint is bound to the plugin, version, files and access.

Host capabilities

  • agent:read, agent:launch to see pane status and resume sessions
  • terminal:read, terminal:send to read the last lines and type the first message
  • workspace:read, notifications:show
  • storage:own, settings:own for history and your settings

Outside the host API

  • Runs the orca CLI: account select, account list, terminal close, terminal send, terminal read (only to ask whether a pane holds unsent text; the panel shows that text when it asks before a manual switch), terminal list (only to see which terminal tab is in front). Always an argument list, never a shell.
  • For a project on a paired Orca server: loads Orca's own runtime client from the app bundle to list and select that server's accounts, and to look up, read-only, which Orca a workspace runs on. These are Orca internals, not a published API
  • Writes its status file and the status line script under ~/.orca/account-rotator/, and, only when you install the console status line, that workspace's .claude/settings.local.json
  • Runs git status and git diff --stat for handoff prompts
  • Never reads tokens, keychains or credential files
  • A handoff prompt carries up to 40 lines of the previous agent's output, so treat it like any pasted terminal output
Install

Two commands and an approval

  1. Install from GitHub. Orca pins the newest version tag and prints what the plugin would be granted, along with a fingerprint.

    orca plugin install ngoohebi/orca-account-rotator

  2. Approve with that fingerprint. The command is printed for you; it looks like this.

    orca plugin install ngoohebi/orca-account-rotator --approve ap1-…

  3. Add a second account for the service in Orca, if you have not already. Optionally set chain in Settings → Plugins → Auto Hand-off to order your accounts. Done: the gauge appears in the status bar.

Coming from cux? Run cux uninstall-hooks first so the two don't both rotate. Every cux setting key has the same name here. Per-directory project bindings and cux attach are not migrated yet.
